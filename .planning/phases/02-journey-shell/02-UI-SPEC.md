# Phase 2 — UI Design Contract: Journey Shell

> Visual and interaction contract for the guided 5-step daily practice flow.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Assumptions (Defaults Chosen Without User Input)

The following choices were made without explicit user confirmation. Review and override before execution begins.

| # | Assumption | Rationale |
|---|-----------|-----------|
| A1 | Leitner review words shown BEFORE the 5 new words each day | Spaced repetition principle: retrieve old before encoding new |
| A2 | Recall step (Step 2) is SKIPPED on Day 1 with a "Day 1 — nothing to recall yet" notice | Nothing to recall on first use; skipping prevents empty state confusion |
| A3 | Filler-word count computed only on speech-to-text transcripts, not typed answers | Filler detection is a speech coaching signal; typed answers don't have verbal filler |
| A4 | Think timer (0:30 or 0:30 for unexpected question) is visual-only — no audio cue | Vanilla JS; Web Audio API adds complexity for marginal gain |
| A5 | 30-day progress grid: collapsed by default on mobile, expanded on desktop | Saves vertical real estate on mobile without hiding it |
| A6 | Resume delete confirmation uses an inline confirm dialog (`window.confirm()`), not a modal overlay | Avoids building a modal component in Phase 2; a modal overlay can replace it in Phase 3 without changing the trigger |
| A7 | Journey step stepper: numbered circles (1–5 + ✓ summary) with connecting line; completed = --green, active = --accent fill, future = --line | Standard step-indicator pattern; no dependency on a component library |
| A8 | The "Coach is thinking" animation HTML is placed in the feedback slot but hidden in Phase 2; Phase 3 removes the `hidden` class | Zero Phase 3 migration cost; self-check rubric occupies the same card in Phase 2 |
| A9 | Unexpected question (Step 5): static offline follow-up prompt is chosen from a small hard-coded array matching the question category | Phase 3 replaces with AI-generated follow-up; the slot is the same |
| A10 | Passcode modal and AI status bar retained verbatim from index.html — no visual changes | Requirement says "keep them and place them sensibly"; they already exist in the right position |

## Spacing Scale

All existing CSS uses ad-hoc values (11px, 13px, 19px, 22px). Phase 2 adopts these rationalized multiples of 4 for new elements. Existing classes (`.card`, `.btn`, `.shell`) keep their current values to avoid a visual regression.

| Token | Value | Usage in Phase 2 |
|-------|-------|-----------------|
| xs | 4px | Icon-to-label gap in stepper, dot gap in thinking animation |
| sm | 8px | Tight internal padding (Leitner badge, filler count chip), step-stepper gap |
| md | 16px | Default card internal spacing, input margin, row gap |
| lg | 24px | Card-to-card gap, section break between vocab words |
| xl | 32px | Journey area top margin, timer top/bottom margin |
| 2xl | 48px | Day summary section top margin |
| 3xl | 64px | Not used in Phase 2 (no page-level hero sections) |

Phase 2 spacing contract note:
- Every spacing value this contract declares is a multiple of 4.
- Existing Phase 1 element padding (`.card`, `.btn`) is unchanged and **not part of the Phase 2 spacing contract** — those values are inherited visual baseline, not new Phase 2 decisions.
- Touch targets: minimum 44px height/width on all interactive elements (accessibility mandate; 44 = 4 × 11).
- Timer display font-size (52px) and thinking animation orb size (36px × 36px) are not spacing values; they are element-dimension annotations carried verbatim from existing files.

- Completed step circle in the journey stepper

The primary focal point of the journey entry screen is the **"Start today's journey" CTA**, centered below the journey progress stepper, full-width on mobile (100% of the content column), max-width 400px on desktop. It is the only `.btn.primary` on the entry screen. Visual hierarchy: stepper (wayfinding) → day/streak stat row (context) → "Start today's journey" button (action). ## Component Inventory

All components are plain HTML/CSS/JS. No external library. Each component below maps to new markup to build in Phase 2.

### 1. Journey Progress Stepper

```
[ 1 Vocab ] — [ 2 Recall ] — [ 3 Speak ] — [ 4 Case ] — [ 5 Interview ] — [ ✓ ]
```

- Horizontal row of numbered circles + connecting lines
- States: future (--line border, --muted text), active (--accent fill, #101827 text), complete (--green fill, #101827 text, checkmark)
- On mobile: circles shrink to 28px, labels hidden, only active step label shown below the row
- Always visible at top of the main content area
- `aria-label="Step N of 5: {step name}"` on each circle
- Current step announced via `aria-current="step"`

### 2. Step Card

Reuses existing `.card` class (--panel background, --line border, 16px border-radius, 19px padding).

Header: `.tag` with time hint + step name | h2 with step title

### 3. Vocab Word Card

```
[ NEW WORD / REVIEW — BOX N ]   [ term ]
Plain meaning: …
Everyday: "…"
PM interview: "…" (shown in a --panel2 callout with left border in --accent, 4px wide)
─────────────────────────────
Your sentence: [ textarea or mic button ]
[ Save ] button
[ ✓ Correct ] or [ Try again ] feedback (shown after save)
```

- Leitner state shown as a `.tag` badge
- PM interview callout: `border-left: 4px solid var(--accent); background: var(--panel2); padding: 12px 16px; border-radius: 0 8px 8px 0`
- "Correct" state: --green, weight 700
- "Try again" state: --muted, with the word's example sentence shown below

### 4. Voice / Type Input Area

```
[ 🎙 Start speaking ]   OR on unavailable: [ ⌨ Type your answer below ]
                                            (one-line notice, --muted, 12px)
```

After recording ends OR during typing fallback:

```
[ editable textarea with transcript ]
Filler words: N   (shown as a small chip below the textarea)
[ Submit answer ]
```

- Mic button: 44px min height, --panel background, --line border; active/recording state: --accent background
- Recording state: "Recording…" label + `.dots` animation (reuse from bakeoff.html)
- Typing fallback notice: single `<p class="small muted">` above the textarea
- Filler chip: `.tag` element positioned below textarea right edge

### 5. Countdown Timer

Reuses existing `.timer` class (52px one-off element size, text-align center, margin 20px — not a type-scale token; see Typography section).

- Think phase: --muted color (not urgent)
- Speak phase: --accent color while > 0:15 remaining; switches to --text when ≤ 0:15
- Expired: timer shows "0:00", no color change, does not block submission
- `aria-live="polite"` on the timer element (announce seconds at :30, :15, :05)
- `@media (prefers-reduced-motion: reduce)`: timer still counts but skip color transition

### 6. "Coach is Thinking" Animation

**Reuse verbatim from bakeoff.html.** Copy the `.thinking`, `.orb`, `.dots`, `.bar.think` CSS and HTML unchanged.

```html
<div id="thinking" class="thinking hidden" role="status" aria-live="polite">
  <div class="orb" aria-hidden="true"></div>
  <div style="flex:1;min-width:0">
    <div><b>Coach is thinking</b><span class="dots" aria-hidden="true">
      <span>.</span><span>.</span><span>.</span></span></div>
    <div class="small" id="thinkMsg">Reading your answer…</div>
    <div class="bar think" style="margin-top:8px">
      <span id="thinkBar" style="width:0%"></span>
    </div>
  </div>
  <div class="stat" id="thinkTime" style="margin:0;font-size:22px">0:00</div>
</div>
```

In Phase 2: this div is always `hidden`. Phase 3 removes `hidden` and starts the animation when an AI call is in flight.

### 7. Feedback Slot

The same `.card` card is used for both the Phase 2 self-check rubric and the Phase 3 AI feedback. The card is always present — never conditionally rendered.

**Phase 2 contents (self-check rubric — COACH-06):**

```
h2: "Self-check"
Checklist (6 items, each a <label class="task">):
  □ Structure — Did I give a clear opening and conclusion?
  □ Clarity — Would a non-PM understand my answer?
  □ PM vocabulary — Did I use PM terms correctly?
  □ Metrics — Did I include a number or measurement?
  □ Impact — Did I say what changed and by how much?
  □ Conciseness — Was my answer under 90 seconds?
[ Done — move on ] button (always enabled)
```

**Phase 3 reserved slot (hidden in Phase 2):**

```html
<div id="aiFeedback" class="hidden">
  <!-- Phase 3 injects: score, what landed, one fix, better line -->
</div>
```

Both the rubric and the AI feedback div share the same parent `.card`. The "Done — move on" button is always enabled regardless of rubric state (COACH-06: AI never blocks the day).

### 8. Resume Upload Area

```
[ Upload PDF resume ] (file input styled as a .btn)
OR (if resume saved):
  Extracted text: [ editable textarea, min-height 200px ]
  [ Replace resume ] [ Delete resume ]
  "Resume saved on this device only." (--muted, 12px)
```

- File input: `<input type="file" accept=".pdf">` hidden, triggered by a styled button
- Textarea: pre-filled with extracted text, editable
- If scan detected (no text extracted): show error copy, replace textarea with a plain textarea for paste

### 9. Streak & 30-Day Grid

```
[ 🔥 N-day streak ]    [ longest: N days ]
─────────────────────────────────────────
[ 30-day grid: circles for days 1–30 ]
```

- Streak number: display size (30px, weight 700), --accent color
- Grid: 6 rows × 5 columns of 24px circles; completed = --green fill; today = --accent fill; future = --line border only; missed = --panel2 fill with --line border
- Grace day: today's circle still --accent (streak maintained), yesterday's circle shows a small dash indicator
- On mobile: grid collapses behind a `<details>` toggle ("Show 30-day progress")

### 10. Day Summary Card

Shown after Step 5 is submitted.

```
h1: "Done for today!"
Stat row: [ Day N/30 ] [ N words learned ] [ Streak: N days ]
Vocab review: "Today's words: term1, term2, … (tap to see meaning)"
[ Export backup ] (secondary .btn)
[ Return to summary ] (not needed; summary IS the final state)
```

## Journey Step Interaction Contracts

### Step 1: Vocabulary (5 new + up to 5 Leitner reviews)

Time hint: `~8 min`

Sequence:
1. If Leitner reviews due: show review cards first (one at a time), "Review — Box N" badge
2. Then show 5 new word cards (one at a time, or all stacked — default: stacked, all visible)
3. Each card: user types or speaks a sentence; "Save" checks usage locally (string-match heuristic against the term; Phase 3 upgrades to AI check)
4. Advance button appears after all cards attempted

**Default sentence check (Phase 2 offline heuristic):** case-insensitive string match — if the submitted sentence contains the term (or its root), mark "Correct". Otherwise mark "Try again" and show the example sentence. This is a placeholder; Phase 3 replaces with AI.

### Step 2: Recall

Time hint: `~5 min`

- Day 1: show "Day 1 — nothing to recall yet" + "Skip to Step 3" CTA
- Day 2+: show yesterday's 5 vocab words (term only, no meaning) + "What was the main fix from your last answer?"
- User types from memory; then reveal shows yesterday's meanings
- No scoring in Phase 2

### Step 3: Spoken Answer

Time hint: `~5 min`

Sequence:
1. Show question (from existing `questions` array in index.html)
2. "Start — 30s to think" CTA → think timer (0:30, --muted, no input)
3. Think timer ends → "Start speaking" CTA appears (or mic auto-starts; default: manual start)
4. Speak timer (1:30, --accent) → mic active or textarea visible
5. Timer expires → transcript/text shown in editable textarea; filler count computed
6. Feedback slot: self-check rubric (Phase 2) or AI feedback (Phase 3)
7. "Save & continue →" CTA (always enabled)

### Step 4: Product Case

Time hint: `~7 min`

- Shows case title + scenario text (from existing `cases` array)
- No think timer; user reads and types/speaks their analysis (no time pressure — matches existing Thinking Lab)
- After submission: same feedback slot (rubric Phase 2, AI Phase 3)
- "Show suggested reasoning" toggle retained from existing think() function

### Step 5: Unexpected Interview Question

Time hint: `~5 min`

Sequence:
1. "Reveal question" CTA (question hidden)
2. Question shown → think timer (0:30)
3. Think timer ends → speak/type answer (1:30)
4. After answer: follow-up question shown (Phase 2: static offline prompt from a small hard-coded array)
5. User answers follow-up (no timer)
6. Feedback slot shown for original answer (Phase 3: covers both turns)
7. "Save & continue →" CTA

## Accessibility Contract

Applies to all Phase 2 elements. These are not negotiable.

| Requirement | Implementation |
|-------------|---------------|
| Keyboard reachable | All interactive elements reachable via Tab; focus order follows visual order |
| Visible focus | `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` on all interactive elements |
| Timer announcements | `aria-live="polite"` on timer element; announce at :30, :15, :05 remaining |
| Thinking animation | `role="status" aria-live="polite"` on `.thinking` div; `.orb` and `.dots` have `aria-hidden="true"` |
| Step stepper | `aria-current="step"` on active step; `aria-label="Step N of 5: {name}"` on each circle |
| Touch targets | All buttons, mic button, Leitner cards: minimum 44px height; min-width 44px where applicable |
| Reduced motion | `@media (prefers-reduced-motion: reduce) { .orb, .dots span { animation: none; } }` — existing from bakeoff.html, carry forward |
| Form labels | All `<input>` and `<textarea>` elements have an associated `<label>` or `aria-label` |
| Microphone state | Mic button `aria-pressed="true"` while recording; `aria-label="Start recording"` / `"Stop recording"` |

## Mobile-First Layout

The app is used on both a Windows laptop (Chrome) and Android phone (Chrome). Mobile-first means the single-column layout is the default; desktop is an enhancement.

| Breakpoint | Layout |
|------------|--------|
| Default (mobile, < 760px) | Single column; `.shell { padding: 14px }`; stepper circles 28px; labels hidden; `#side` hidden (no sidebar needed — journey is linear) |
| Desktop (≥ 760px) | Max-width 760px centered (narrower than the existing 1160px — journey is a linear flow, not a dashboard); stepper full-width with labels |

The existing 1160px max-width and two-column `.layout` grid are NOT used for the journey shell. The journey is a single centered column, max-width 760px, to work naturally on mobile and prevent uncomfortable line lengths on desktop.
