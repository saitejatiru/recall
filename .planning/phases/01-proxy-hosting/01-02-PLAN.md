<task type="checkpoint:human-action" gate="blocking">
  <name>Checkpoint: Cloudflare Worker deploy — secrets, variables, KV</name>
  <what-built>
    worker/worker.js is now on GitHub. This checkpoint deploys it to Cloudflare,
    adds encrypted NIM keys and passcode, sets plain-text variables, and creates
    the KV namespace for the daily cap counter.
  </what-built>
  <read_first>
    - docs/SETUP.md Sections 2, 3, and 4 (Cloudflare Worker deploy, Secrets/Variables, KV)
    - .planning/phases/01-proxy-hosting/01-RESEARCH.md "Secrets and Variables" table
  </read_first>
  <how-to-verify>
    Follow these steps exactly (all in Cloudflare Dashboard at dash.cloudflare.com):

    Step 1 — Create a free Cloudflare account at cloudflare.com if you do not have one.

    Step 2 — Workers & Pages → Create → Worker → name it `recall-proxy` → Deploy.

    Step 3 — Click "Edit Code" in the Worker page → delete ALL placeholder code →
    paste the entire contents of `worker/worker.js` from your repo → Save and Deploy.

    Step 4 — Worker Settings → Variables → Secrets section → Add Secret (four times):
      NIM_KEY_1  = your first NVIDIA NIM API key (paste, check "Encrypt") → Save
      NIM_KEY_2  = your second NVIDIA NIM API key → Save
      NIM_KEY_3  = your third NVIDIA NIM API key (or skip if you only have two) → Save
      PASSCODE   = choose a memorable passphrase e.g. recall-train-2026 → Save
    IMPORTANT: These must be in the Secrets section (encrypted), NOT in the Variables section.
    Your NIM keys start with nvapi- — never paste them anywhere else.

    Step 5 — Variables section (plain text, not encrypted) → Add Variable (four times):
      ALLOWED_ORIGIN = https://saitejatiru.github.io
      PRIMARY_MODEL  = nvidia/nemotron-3-super-120b-a12b
      FALLBACK_MODEL = nvidia/nemotron-3.5-lightning-30b-a3b
      DAILY_CAP      = 300

    Step 6 — Storage and Databases → KV → Namespaces → Create namespace:
      Name: recall-ratelimit → Add.

    Step 7 — Back to Worker → Settings → Functions → KV Namespace Bindings → Add:
      Variable name: KV → KV namespace: recall-ratelimit → Save and Deploy.

    Step 8 — Note your Worker URL. It is shown at the top of the Worker page:
      e.g. https://recall-proxy.yourusername.workers.dev
      RECORD THIS URL — you will need it in Plan 01-03.

    Step 9 — Quick smoke test (using curl from Git Bash / WSL, replace YOUR_WORKER_URL):
      curl -s -X POST YOUR_WORKER_URL \
        -H "Origin: https://saitejatiru.github.io" \
        -H "Content-Type: application/json" \
        -d '{"task":"ping"}'
    Expected output: {"error":"auth_failed"} with HTTP 403 (no passcode = rejected).
    This confirms the Worker is live and auth is working.
  </how-to-verify>
  <resume-signal>Type your Worker URL (e.g. https://recall-proxy.yourname.workers.dev) when setup is complete, or describe any issues.</resume-signal>
  <acceptance_criteria>
    - Worker `recall-proxy` is deployed and responding at its workers.dev URL
    - Smoke test curl (no passcode) returns 403 auth_failed
    - NIM_KEY_1, NIM_KEY_2, NIM_KEY_3, PASSCODE are in Secrets (encrypted, not Variables)
    - ALLOWED_ORIGIN, PRIMARY_MODEL, FALLBACK_MODEL, DAILY_CAP are in Variables
    - KV namespace `recall-ratelimit` exists and is bound as `KV`
  </acceptance_criteria>
  <done>
    Worker is live. Auth is confirmed working (no-passcode → 403). Worker URL is recorded

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | git push to public repo | high | mitigate | Pre-commit hook (activated in this plan via `git config core.hooksPath`) scans staged files; GitHub push protection provides second layer |
| T-02-02 | Information Disclosure | Cloudflare Secrets UI | high | mitigate | Secrets are entered directly in Cloudflare dashboard (encrypted at rest); they never appear in any file, clipboard history, or terminal output — only pasted into the Secrets input field |
| T-02-03 | Spoofing | wrong Worker URL noted | low | accept | Worker URL is not secret; if recorded incorrectly, Plan 01-03 config.js update fails to connect — correctable |
| T-02-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package manager installs in this plan |
</threat_model>
