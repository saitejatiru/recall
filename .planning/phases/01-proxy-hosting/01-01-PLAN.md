## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Worker | Untrusted: origin header, body with passcode and task payload arrive from public internet |
| Worker → NIM API | Trusted outbound: Worker constructs request; NIM keys never reach browser |
| Repo → GitHub (public) | Any committed file is immediately public; secrets must never be in any committed file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | repo (committed files) | high | mitigate | `.githooks/pre-commit` scans staged diffs for NVIDIA API key patterns on every commit; GitHub push protection auto-detects the same pattern on public repos (enable in Settings → Code security → Push protection) |
| T-01-02 | Tampering | config.js | high | mitigate | By design: config.js holds Worker URL only (not secret); PASSCODE is entered by user and stored in `localStorage.passcode`, never committed — enforced by SETUP.md and pre-commit hook |
| T-01-03 | Information Disclosure | Worker logs (Cloudflare) | high | mitigate | Worker code never references `env.NIM_KEY_*` in `console.log` or response bodies; only task type, error codes, and latency are logged |
| T-01-04 | Information Disclosure | Worker → browser response | high | mitigate | Task-based contract: Worker owns all system prompts and model parameters; browser receives only the response shape (`{ok}`, `{results}`, or `{error}`), never raw NIM output with system prompt echoed |
| T-01-05 | Elevation of Privilege | prompt injection via user answers | high | mitigate | Task-based contract established in Phase 1: Worker constructs all system prompts from internal constants; user payload (answers, resume text in Phase 3) is data, never instructions — enforced architecturally |
| T-01-06 | Spoofing | passcode brute force | medium | mitigate | KV daily cap (300 requests/day default) limits blast radius; an attacker with the correct origin can burn at most 300 calls before the cap cuts off; cap is adjustable in Cloudflare dashboard |
| T-01-07 | Spoofing | Origin header forgery via curl | low | accept | Origin header is anti-bot (not anti-human); passcode provides a second factor; for a free personal tool with KV daily cap the residual risk is documented and accepted (see RESEARCH.md Pitfall 2) |
| T-01-08 | Denial of Service | KV write exhaustion | medium | mitigate | KV put() is wrapped in try/catch; on KV failure the request continues (better to serve than block); KV errors logged to Worker console; at ~10 req/day normal usage, the 1K writes/day free limit is never reached |
| T-01-09 | Repudiation | no requestor identity beyond passcode | low | accept | Personal single-user tool; passcode is sufficient identity signal; audit via Cloudflare Worker logs |
| T-01-SC | Tampering | npm/pip/cargo installs | n/a | accept | Phase 1 has no package manager installs; vanilla JS, no build step — supply chain attack surface is zero |
</threat_model>
